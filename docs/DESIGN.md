# Frontend design notes

The UI uses [shadcn/ui](https://ui.shadcn.com) on [Base UI](https://base-ui.com) with Tailwind v4. Read this before adding a screen, and update it when you introduce a new pattern.

## Setup facts

- shadcn components live in `src/components/ui` (generated by `npx shadcn@latest add <name>`; config in `components.json`). Import them with the `@/` alias.
- Theme tokens are CSS variables in `src/styles/index.css` (`--background`, `--primary`, `--muted`, ...). Use the Tailwind names (`bg-background`, `text-muted-foreground`, `border-border`), not raw colours.
- Dark mode: the `dark` class on `<html>`. `App.tsx` toggles it from `prefers-color-scheme`.
- Routing: use `AppLink`, `TextLink` and `LinkButton` (`components/AppLink.tsx`) for navigation. In-app paths use React Router; URLs starting with `/api/` or `http(s)://` stay plain anchors, which is how the Install button reaches the backend. Sidebar items use `render={<AppLink href=... />}`.
- Toasts: `toast` from `sonner`; `<Toaster />` is mounted in `Providers`.
- Icons are Phosphor (`@phosphor-icons/react`), regular weight, `*Icon` names.

## App components (`src/components`)

| Component | Purpose |
|---|---|
| `PageHeader` | Page title, description and actions; every dashboard page starts with it |
| `StatCard` | One metric on a `Surface` |
| `QueryBoundary` | Shared loading (Spinner) and error (Alert with retry) handling for a query |
| `ReviewsTable` | Reviews list with empty state, used on three pages |
| `Badges` | Maps verdicts, review status, index status and severity to coloured badges |
| `BarSeries` | Dependency-free bar chart from theme tokens |
| `Text`, `Surface`, `Field`, `SimpleSelect`, `MeterBar` | Small helpers over the shadcn primitives |
| `Brand`, `AppLink` | Logo lockup; router bridge |

## Patterns

- Every data view has loading, empty and error states. Use `QueryBoundary` and an `Empty` with one action.
- One primary action per view (the default `Button`).
- API types are generated from the backend: `make api-types`. Never hand-write response types.
- The dashboard is lazy-loaded (`App.tsx`) so the landing page stays small.
